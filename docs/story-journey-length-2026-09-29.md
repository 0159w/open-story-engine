## 已确认的产品基线

本轮先实施优先级最高的整局篇幅规划。母本仍为十万汉字以上的官方长篇，单局按玩家实际阅读和选择的体验设计，不要求读完或重新生成整部母本。

| 指标 | 默认目标 |
| --- | --- |
| 完整一局 | 约 150 分钟，通常 120～180 分钟，可分次完成 |
| 实际正文 | 约 30000 汉字，规划区间 25000～40000 汉字，包含开局和结尾 |
| 互动 | 约 45 回合，参考区间 40～60 回合，不含身份开局 |
| 单次游玩 | 希望 30～45 分钟能得到阶段成果并自然暂停 |
| 较长路线的设计参考 | 玩家主动深入且有实质内容时，约 4～5 小时、4～6 万汉字 |

这些是用户确认的设计假设，不是已测出的阅读速度、通关时间或最大耐受时间。本次先实现默认预算，不新增长短模式选择器，也不自动把预算延长至六万字。真实耗时包含阅读、思考、输入和未重叠的生成等待，挂机时间不参与剧情调度。单回合保留现有动态长度，不设置总篇幅放行门槛。

## 实现

- `story_journey.py` 管理分支上的 `storyJourney`。预算由代码确定，计量从已保存祖先链的正文重新计算，不信任模型计数；兄弟分支、未选草稿、重复请求和单纯方向菜单不累计到当前路线。旧存档首次通过当前规划器续写时重建计数，不修改历史正文。
- 新的真实模型开局保存预算，第一次互动在原有 `reader.context_plan` 调用中形成角色故事计划。模型围绕所选身份、关系、资源、牵挂和世界条件写五阶段的前提、核心问题、阶段目标和伏笔/后果安排。它与原著章节独立，晚出场角色也不会自动进入收尾。
- 五阶段的累计字数参考是 4500、10500、18000、25000、30000。字数和回合使用量只提醒规划器调整推进密度，不证明阶段完成，也不决定玩家行动。后段逐渐回收冲突，超预算优先准备合理收束，不不断添加长期义务。
- 计划保存于分支叙事元数据，标记 `future_possibilities_not_facts`，通过 ContextBundle 的输出目标传递，绝不进入 `BranchState` 或事实记忆。沿用有效计划；当玩家改道、永久后果使原路径失效或预算要求调整时，由同一次规划调用修订未来安排，保留修订原因。
- 写作收到修订后的计划，仍以当前行动和既成事实为准。新增实体实际出现后沿用现有状态提取流程登记，不因计划提到便提前生成权威实体。
- 原有状态提取调用可返回 `journeyEnding`，表示当前正文已经叙述的整局终局。代码只核对字段和当前段落的逐字引用，并与交付凭据绑定，不再增加语义审核调用。无法确认、格式无效或提取失败时保留正文和可继续状态。模型可能误判终局语义，仍须直接阅读实际输出验证。
- 新规划路线不再因原著节点处于最后一章而自动结束。仅到字数、回合、阶段配额或空菜单均不结束。已观察到的自然终局走现有路线生命周期保存；有充分因果的提前终局不为了凑篇幅继续。
- `/journey` 增加 `playthrough_length`，仅包含预算和实际计数。暂定的未来章节、冲突和结局不投射为玩家进度条，也不泄露到选项。

没有增加模型调用、重写流程或正文审核。母本保持官方长篇；本轮未切换正文模型和服务商配置，配图优化仍属其他方向。

## 验证口径

自动化需要覆盖：同一路线计数、重复请求不增量、分叉隔离、旧存档继承、规划缺失或损坏、超预算仍正常交付、原著终点可继续、提前自然终局、终局引用与请求凭据绑定，以及未来计划不会进入事实状态或公开视图。

真实游玩必须从官方身份正常开局，保存每次行动、完整正文、计划和计数。短抽样只能证明链路能用；最终篇幅、故事完整性和实际玩家时长须分别验证，不把离线模拟或模型填写的计划视为完整通关验收。

本轮一条真实角色路线经过 23 次互动、30618 汉字产生自然终局记录，落在规划区间；全部正文已直接阅读，仍有承接和细节矛盾，且尚未测量真人时长。23 回合即达 3 万字说明 45 回合只能作为参考，不能与总字数同时作为硬指标。完整证据与验收边界见 [真实游玩与回归记录](evidence/story-journey-2026-09-29/review.md)。

## 2026-09-30 后续优化

逐回合复核既有计划，保存 `revision`、`review.decision/reason/nextMilestone`；形状不合法或修订缺失仅记录不可用，保留旧计划和已生成正文，不重试改写。加入最近三个祖先节点的实际末段、行动及摘要，帮助避免重复与错误承接；这些文字中的转述仍不是权威事实。两身份真实改道与较长新路线记录见 [本轮验证](evidence/optimization-2026-09-30/review.md)，仍发现行动表达和重复问题，不能据此宣称内容质量已全部通过。

## 2026-09-30 篇幅专项：让阶段规划对照实际成果

用户最新要求优先优化篇幅；开场建议「可跳过短序章 → 角色选择 → 首次行动提示」已接受，待本方向之后实施。配图、Jev、其他界面方向仅保留问题清单，暂停新增优化。

此前真实记录中，角色已经下山、找到工作与住处，却连续多回合仍被笼统归为“在青石镇立足”。原有五阶段规划和下一成果安排没有持续对照正文结果，容易重复入住、核账、等待等过程。

- 原有状态提取调用新增可选 `journeyProgress`，记录一个实际新结果及其所在段落、逐字引用。保存为 `lastOutcome`，与写前的 `nextMilestone` 分开；下一回合同时收到原安排和已写结果。引用校验只检查记录绑定，不能证明模型的语义概括正确。缺失、无效或提取失败时结果记为未知，正文照常保存，不重试、不改写、不加模型调用。
- `journeyReview.phaseId/phaseReason` 保存规划器对本回合阶段的判断及原因。`phaseWindow` 从当前祖先链统计连续同阶段的实际字数与互动，不累计兄弟分支或方向菜单；改计划不会清零已读字数。同阶段累计达到对应阶段字数参考，或总体预算提醒已领先当前阶段时，提示重新考虑推进密度。没有阶段记录的旧档不猜测历史阶段。
- 真实复核发现只加提醒仍会沿用陈旧提纲，因此增加 `planning_view`：同阶段提醒存在且当前预算阶段尚未成功重排时，只在原有规划调用的输入里暂不提供旧未来提纲，要求基于当前事实与剩余预算重新编排。`planBudgetPhase` 记录成功规划时的预算阶段，避免同一预算阶段每回合重做；生成或结构失败则保留原计划，下一次正常行动再处理，不在本回合隐藏重试。总预算、历史正文、权威状态均不重置。
- 阶段判断、停留统计及成果笔记均为叙事规划信息，不改动权威事实、目标完成状态或路线生命周期；不公开未来提纲或伪造完成百分比。提醒不意味着必须升级阶段，不强迫跳时、制造事故或结束。
- 规划和写作要求把已授权的重复过程合并为过渡，现有单回合动态篇幅用于新结果、关系变化、选择与代价。改道只重排剩余故事，不重开完整预算；不同阶段不能只是同一手续的拆分。新交易、风险承诺等仍由玩家决定，主动日常体验照常回应。

代码与连续实测证据见 [篇幅专项验证](evidence/story-pacing-2026-09-30/review.md)。真人通关时长、稳定自然收束率与故事吸引力仍需分别验证。
